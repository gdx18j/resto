# Restaurant Recommendation System

Веб-приложение для ресторана на Django. Проект позволяет хранить меню, состав блюд, пищевую ценность и информацию об аллергенах. В дальнейшем система будет рекомендовать пользователю подходящие блюда с учётом его предпочтений и ограничений.

## Основная идея

Каждое блюдо состоит из отдельных ингредиентов. Ингредиенты, в свою очередь, могут быть связаны с аллергенами.

Например:

```text
Маргарита
├── Сыр моцарелла
│   └── Аллерген: молоко
├── Пшеничная мука
│   └── Аллерген: глютен
└── Помидор
    └── Аллергенов нет
```

Благодаря такой структуре система может автоматически определить, какие аллергены присутствуют в блюде.

## Структура приложений

На данный момент проект разделён на несколько Django-приложений:

* `accounts` — пользователи и данные аккаунта;

* `main` — основные страницы сайта;
* `config` — настройки Django-проекта.

## Модели меню

### Category

Категория блюда, например:

* пицца;
* салаты;
* супы;
* десерты;
* напитки.

### Allergen

Отдельный аллерген, например:

* молоко;
* яйца;
* глютен;
* арахис;
* рыба.

У каждого аллергена есть название и уникальный системный код.

### Ingredient

Отдельный ингредиент блюда. Один ингредиент может содержать несколько аллергенов.

Например, майонез может быть связан одновременно с аллергенами «Яйца» и «Горчица».

### Dish

Основная модель блюда. В ней хранятся:

* название;
* описание;
* категория;
* фотография;
* цена;
* вес порции;
* калории;
* белки;
* жиры;
* углеводы;
* время приготовления;
* доступность для заказа;
* отображение блюда в меню;
* возможные следы аллергенов.

### DishIngredient

Промежуточная модель между блюдом и ингредиентом.

Она хранит информацию о том, как конкретный ингредиент используется в конкретном блюде:

* количество;
* единица измерения;
* возможность убрать ингредиент;
* дополнительное примечание.

Структура связи:

```text
Dish → DishIngredient → Ingredient → Allergen
```

## Работа с аллергенами

Модель блюда содержит методы для получения всех его аллергенов и проверки конфликта с заданным списком ограничений.

Учитываются:

1. аллергены, содержащиеся в ингредиентах;
2. возможные следы аллергенов, указанные непосредственно у блюда.

Например, если пользователь указал аллергию на молоко, а блюдо содержит сыр, система обнаружит конфликт.

Аллергия не должна полностью запрещать заказ блюда. Пользователь может заказывать еду не только для себя. Поэтому планируется следующая логика:

* конфликтующие блюда не попадают в персональные рекомендации;
* в общем меню они остаются доступными;
* возле блюда отображается предупреждение;
* добавить блюдо в корзину всё равно можно;
* перед оформлением заказа показывается общее предупреждение об аллергенах.

## Django Admin

Через административную панель уже можно:

1. создавать категории;
2. добавлять аллергены;
3. создавать ингредиенты и назначать им аллергены;
4. создавать блюда;
5. указывать КБЖУ, цену, фотографию и описание;
6. добавлять ингредиенты непосредственно внутри формы блюда;
7. указывать возможные следы аллергенов;
8. управлять доступностью блюд.

## Работа через Docker

Проект запускается с помощью Docker Compose.

Запуск контейнеров:

```bash
docker compose up --build
```

Запуск в фоновом режиме:

```bash
docker compose up -d
```

Остановка контейнеров без удаления базы:

```bash
docker compose down
```

Остановка с полным удалением тома PostgreSQL:

```bash
docker compose down -v
```

Команда с `-v` удаляет все данные базы, поэтому используется только при необходимости полного пересоздания PostgreSQL.

Команды Django выполняются внутри контейнера `web`:

```bash
docker compose exec web python manage.py makemigrations
docker compose exec web python manage.py migrate
docker compose exec web python manage.py createsuperuser
```
